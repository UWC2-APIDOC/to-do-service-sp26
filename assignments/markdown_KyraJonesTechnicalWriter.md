# Using Markdown to Write Documentation

There are several advantages to writing your documentation in Markdown. Similarly, there are also a few disadvantages. This article will discuss these so that you can make the decision based on what would work best for you and your end-user. 

## Advantages

1. Now more than ever, Markdown proves to be an exceptionally good coding language for one core reason: AI.

The same drive for simplicity that resulted in Markdown's creation makes it a language easily parsed by AI. While AI seems to be a never-ending topic of discussion as of late, it is true that most businesses and many individuals nowadays have or plan to use AI for their own needs.

2. Simple documents are often easier to read than complex ones.

Have you ever talked to someone who beat around the bush the entire conversation? Maybe you were making a sandwich in their house and needed to know where the tomatoes were and instead of answering your question, they began a dramatic recapping of their tumulteous grocery store endeaveor to get said tomatoes? Sometimes that is how reading overly complicated documents feel. While the context is nice for those that are curious, the majority of readers just want an answer. 

3. Modern-day version control may have been intially began as a tool for coding, but it's basically a writer's dream come true.

Git is an amazing tool for backing up both code and writing. (And yes, the Git in GitHub and GitLab comes from the incredibly versitile version control system, Git.) 

## Disadvantages

While most Markdown nowadays is some kind of stylized Markdown (GitHub-flavored is one such example), the standard language is quite limited.
