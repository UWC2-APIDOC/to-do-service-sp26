# Using Markdown to Write Documentation

Writing your documentation in Markdown has both advantages and disadvantages. This document will discuss these so that you can make the decision based on what would work best for you and your end-user.

## Advantages

1. Now more than ever, Markdown proves to be an exceptionally good coding language for one core reason: AI.

    The same drive for simplicity that resulted in Markdown's creation also made it a language perfect for AI consumption. While AI seems to be a never-ending topic of discussion, there is a reason for it. As most businesses and individuals nowadays have already used or have plans to use AI, it's an important consideration when deciding how to create documentation.

2. Simple documents are often easier to read than complex ones.

    Have you ever talked to someone who refused to get to the point? Perhaps you were making a sandwich in their house and needed to know where the tomatoes were and instead of answering your question, they began a dramatic recapping of their tumultuous grocery store trip to get said tomatoes?

    Sometimes that is how reading an overly complicated document feels. While the context can be nice for those that are genuinely curious, most readers want a straight answer.

3. Modern-day version control may have been initially began as a tool for coding, but it's basically a writer's dream come true.

    While version control is available in different tools nowadays, if you work in a software company that already uses Git, it's more cohesive to use the same tool as your peers. And software that use Git for version control (such as GitHub and GitLab), often have built-in Markdown editors and even "flavored" Markdown. This makes it easy for your peers to access the documentation when needed without having to leave the workspace.

4. Different "flavors" of Markdown allow for extended syntax.

If you find you don't enjoy writing in Markdown due to the lack of features or abilities that you can find in more mainstream document editors, then flavored Markdown is for you. "Flavored" Markdown is standard Markdown with special syntax added. For example, GitHub has a GitHub-flavored Markdown that allows strikethroughs, something standard Markdown doesn't support.

## Disadvantages

1. While most Markdown nowadays is some kind of flavored Markdown, there are limits to the standard language.

    For example, you can create headings, blockquotes, inline code, and lists, but cannot customize them. While this may frustrate some, the beauty of Markdown is the simplicity, which is why it forgoes fancy colors and fonts. Often this doesn't pose a problem to developers and more technical end-users, but when creating documentation for those who might learn best with visual aids, Markdown is not ideal.

2. You can't use flavored Markdown everywhere.

    Since there are hundreds of different flavors of Markdown, not every editor or Markdown previewer supports these customizations. That means, if you take a GitHub-flavored Markdown document and put it into an editor that doesn't support it, the syntax will not show and the document will show the broken Markdown tags.

## How Do I Decide?

As great as Markdown is, there are certain situations that require a different language or tool. If you need to decide whether to use Markdown or something else, ask yourself the following questions:

1. Who are my end-users?
2. What is the goal of the document? Should there be a lot of videos or interactive elements?
3. Where will the end-users view this documentation?
4. Does the site or tool the documents live on support different flavors of Markdown?

If you consider your answers to the questions above, you shouldn't have too hard of a time deciding if Markdown is right for you.

## Conclusion

Ultimately, the choice of how you write your documents is entirely up to you. Since there are lots of aspects to consider, there is no set answer for what is best. You are the one who knows the situation best and can decide if Markdown is a good fit. The one piece of advice I can give is to weigh your options and be willing to adjust your current methods to fit those needs, even if you need to learn a new skill along the way.
