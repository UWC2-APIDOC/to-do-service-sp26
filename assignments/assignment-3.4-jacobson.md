# Markdown Overview

The [Markdown Guide](https://www.markdownguide.org/) describes markdown as:
>"...a lightweight markup language that you can use to add formatting elements to plaintext text documents."

Keep reading to learn more about the benefits and limitations to using markdown.

## Markdown Benefits

* Allows you to create styled text *without* embedding complex formatting tags in the documentation text.
  
* It is relatively easy to learn and the notation is unobtrusive, making it easy to read markdown files.

* Markdown is preferred by AI models. This is because they are trained on code and formatted text.

## Markdown Limitations**

* Too lightweight to support documentation with complex layouts, global linking, and specific typography.

* Can be intimidating to non-technical reviewers who are used to WYSIWYG editors.

* There are many variations of markdown. Before you start a project, you **must** to check which variation the documentation publishing tool uses.

## Helpful Markdown Tips and Resources

Here are my tips for working with markdown:

* Identify the variation of markdown your documentation publishing tool uses and google a cheat sheet for that variation.

* If you are working in a README.md file in Github, I do not recommend making changes online as this will create a messy commit log in the repo. Instead, make your changes and commits in the clone of your repo on your personal computer.

* If you are using VScode on a Mac, click **CMD-K, V** to display a rendered markdown file. This can help identify errors in your notation.
